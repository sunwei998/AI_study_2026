## 修复：模型编辑/禁用、用户编辑接口 500

### 根因
第三轮给 update_model / update_dim_value / update_user 加「字段级 diff 日志」时，三个 diff 函数里用了 `old.get(...)`。但 `db.fetch_one()` 返回的是 `sqlite3.Row`（**无 .get() 方法**），运行时抛 `AttributeError` → 500。
- 涉及：`PUT /models/{id}`（编辑保存 + 禁用共用一个接口）、`PATCH /users/{id}`、`PUT /dim-tables/{id}/values/{id}`。

### 修复

### 验证
- 单元测试：用 `conn.row_factory=sqlite3.Row` 取真实 Row 传三个函数，无异常、diff 正确。
- TestClient 端到端：模型原值 PUT 200、用户 PATCH 200、非默认模型禁用/恢复 200。
- 8000 端口运行中服务（--reload 已自动加载新代码）PUT /models 也 200。

### 教训（已写入 MEMORY.md）
纯函数 helper 用普通 dict 做单元测试测不出 sqlite3.Row 的 .get() 缺失，必须用真实 Row 回归。

## 修复：导入导出操作人筛选下拉被筛选面板挡住

### 现象
AdminTransferRecords 操作人列用 filterType:'select'，点开 AppTable 筛选面板后，再点 AppSelect 展开下拉，下拉选项被筛选面板盖住。

### 根因（两处）
1. **z-index**：AppSelect 下拉面板 `.as-panel` z-index=3000，而 AppTable 筛选面板 `.app-table__filter-panel` z-index=10001（toggleFilter 里内联写死），3000 < 10001 被盖住。
2. **点击外部误关**：AppSelect 下拉 Teleport 到 body（在 filterPanel DOM 外），点选项时 AppTable 的 `onFilterDocClick`（capture 阶段）判断 target 不在 filterPanelRef 内 → closeFilterPanel，选择丢失。

### 修复
- AppSelect.vue：`.as-panel` z-index 3000 → 11000（高于 10001）。
- AppTable.vue：`onFilterDocClick` 加 `.as-panel` 豁免（与 `.app-table__filter-btn` 同类处理），点下拉选项不关筛选面板。

### 教训
Teleport 到 body 的下拉（AppSelect 的 .as-panel）在「弹层套弹层」场景下：z-index 要盖过外层弹层；外层弹层的「点击外部关闭」逻辑要用 `.closest('.as-panel')` 豁免，否则点下拉会误关外层。

## 操作人筛选改多选（AppSelect 支持多选 + 宽度折叠 +N）

### 需求
操作人下拉支持多选，tag 回显名称，按实际宽度自动折叠（选中 3 个但只能显示 1 个时显示「a +2」），UX 借鉴 element-plus。

### 改动（5 文件）
- **AppSelect.vue**：新增 `multiple` prop（默认 false，单选向后兼容）。多选时 modelValue 是数组、选项加 checkbox（点击 toggle 不关下拉）、trigger 回显 tag（含 × 删除）、按宽度折叠显示 `+N`。
  - 折叠算法：隐藏测量层 `.as-measure`（屏幕外 visibility:hidden 保留布局可量 offsetWidth）渲染全部 tag；`ResizeObserver` 监听 trigger + watch 选中变化，逐个累加 tag 宽度（gap 4）直到超出 `.as-tags` 容器 clientWidth，`visibleCount = max(1, n)`，剩余折叠 `+N`。
- **AppTable.vue**：`TableColumn` 加 `filterMultiple`；filterPanel 状态加 `filterMultiple`；select 筛选分支按 multiple 传 AppSelect（数组 modelValue + `selectFilterOptions` 不含「全部」）；`onSelectChange` 多选时直接取数组。
- **AdminTransferRecords.vue**：username 列加 `filterMultiple: true`；`usernameFilter` 改 `string[]`；onFilterChange/load/watch 相应改数组。
- **adminService.ts**：PaginationParams 加 `usernames`；fetchTransfers 传 `usernames.join(',')`。
- **admin.py**：`list_transfers` 的 `username` 从单值 `username = ?` 改成逗号分隔多选 `username IN (...)`（单值仍兼容）。

### 验证
- 后端 py_compile + TestClient：transfers 多选 username（admin,GOD）与单值均 200。
- 前端 type-check + build 通过；AppSelect/adminService 零 lint，AdminTransferRecords 仅既有 `Record<string,any[]>`。

### 关键点
- 折叠测量用「独立隐藏测量层」而非在主 trigger 里 display:none，因为 display:none 的 offsetWidth=0 无法量，visibility:hidden 可量。
- 单选「全部」选项多选时不注入（空数组即全部）。

## 修复（二次）：操作列 hover 仍透出 —— CSS 特指度相同被后定义覆盖

### 现象
上轮把 fixed 列背景改不透明后，用户反馈 hover 操作行时操作列仍"变透明"，下方按钮透出。

### 根因
上轮的 fixed 列 hover 规则 `.app-table__row:hover .app-table__td--fixed-left`（特指度 0,3,0）写在 1502 行，但通用的 `.app-table__row:hover .app-table__td`（也是 0,3,0）在 1601 行**靠后**，特指度相同时后定义者胜 → 半透明 `primary 5% transparent` 又把 fixed 列盖回透明。
另有：stripe 斑马纹（0,5,0）、selected/current（0,2,0 且带 !important）都会压过基础 fixed 规则。

### 修复（AppTable.vue）
fixed 列背景全部加 `!important`：
- 基础 `.app-table__td--fixed-*` → `var(--color-surface) !important`（压过 stripe/通用 hover）
- hover → `color-mix(surface 95%, primary 5%) !important`
- selected → `color-mix(surface 90%, primary 10%) !important`
- current → `color-mix(surface 92%, primary 8%) !important`

### 教训（已写入 MEMORY.md）
修复 CSS 覆盖问题前，先算特指度 + 看规则在文件中的先后位置；同类选择器特指度相同时，后定义覆盖前定义。要"压过所有状态"最稳的是加 `!important`。
