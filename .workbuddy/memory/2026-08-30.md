## 修复（二次）：操作列 hover 仍透出 —— CSS 特指度相同被后定义覆盖

### 现象
上轮把 fixed 列背景改不透明后，用户反馈 hover 操作行时操作列仍"变透明"，下方按钮透出。

### 根因
上轮的 fixed 列 hover 规则 `.app-table__row:hover .app-table__td--fixed-left`（特指度 0,3,0）写在 1502 行，但通用的 `.app-table__row:hover .app-table__td`（也是 0,3,0）在 1601 行**靠后**，特指度相同时后定义者胜 → 半透明 `primary 5% transparent` 又把 fixed 列盖回透明。
另有：stripe 斑马纹（0,5,0）、selected/current（0,2,0 且带 !important）都会压过基础 fixed 规则。

### 修复（AppTable.vue）
fixed 列背景全部加 `!important`：
- 基础 `.app-table__td--fixed-*` → `var(--color-surface) !important`（压过 stripe/通用 hover）
- hover → `color-mix(surface 95%, primary 5%) !important`
- selected → `color-mix(surface 90%, primary 10%) !important`
- current → `color-mix(surface 92%, primary 8%) !important`

### 教训（已写入 MEMORY.md）
修复 CSS 覆盖问题前，先算特指度 + 看规则在文件中的先后位置；同类选择器特指度相同时，后定义覆盖前定义。要"压过所有状态"最稳的是加 `!important`。

## 维表字段配置化（Layer 1+2，后端）

### 结论先行
评审后确认**不做完整字段管理 UI**：本项目的维表是被代码消费的下拉源（`fetchDimValuesByCode` 灌 select），不是业务实体。主流做法里 Stripe/Shopify 这类 SaaS 后台 schema 归代码管，只有低代码平台（简道云/Airtable）才把字段管理当产品。

真正的痛点不是"缺字段管理"，而是 `model_provider` 特例硬编码 **后端 4 处 + 前端 9 处**。走中间路线：把已有 spec 从 Python 常量下沉到 DB，物理列保持固定超集。

`dim_values` 的物理列**本来就是 7 列超集**（code/name/name_en/api_key/sort_order/enabled/remark），所以配置化**不需要改表结构**，只新增 `dim_table_fields`。

### 已实现（后端，前端 Layer 3 待做）

- **admin.py**：`_dim_value_field_spec(table_code)` → `(table_id, table_code)`，优先读 DB（`enabled=1`），**查不到回退代码模板**（老库零风险）；新增 `_dim_spec_item` / `_dim_spec_from_template` / `_spec_label_table`；export / template / import 三个调用点同步。
- **新接口**：`GET /dim-tables/{id}/fields`（无配置时返回模板 + `persisted=false`）、`PUT /dim-tables/{id}/fields`（`require_settings_admin` 即 super/system，upsert）。`POST /dim-tables` 建表即写默认字段。
- **消灭的特例**：模板示例行由 spec 逐列生成（不再 `if is_provider`）、bool 列下拉按 `is_bool` 遍历（不再写死 enabled）、`api_key` 脱敏改按 `field_type == "secret"`（不再 `k == "api_key"`）。

### 两个必须记住的坑
1. **field_key 会拼进 SQL**（import 里 `set_clause = f"{k} = ?"`、`INSERT INTO dim_values ({cols})`），所以必须白名单校验 `DIM_PHYSICAL_COLUMNS`。PUT 接口拒非法 key（422），spec 读取时再过滤一次做纵深防御。
2. **code / name 是导入定位行的依据**，配置层面强制 `enabled=1` + `required=1`，忽略请求里的相反设置；spec 里若被关掉也会强制补回。

### 语义约定（写进文档）
关闭某列 = 不出现在导出与模板里；导入时该列不更新，**库里历史值保留**（e2e 已验证）。不是"删字段、删数据"。

### 兼容性彩蛋
改了列头标签后，**旧标签的历史文件仍能导入** —— 因为 `_resolve_headers` 是「模块 labels 优先 → 全局静态别名表兜底」，旧标签在静态表里还在。e2e 有专项用例。
