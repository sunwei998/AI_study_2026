## 4. 修复：is-hidden 的 tab 条仍占 21px 空间

用户在 DOM 里发现侧栏展开、tab 为 `is-hidden` 时元素**依然占据空间**。属实，是我的疏漏。

根因：**`max-height: 0` 压不掉 padding 与 border**。`box-sizing:border-box` 下 max-height 约束 border-box，但 padding+border 为非负固定值、内容盒不能为负只能钳到 0，元素最终高仍 = padding(12+8) + border(1) = **21px** 幽灵条。

用 Chrome headless 实测三种状态确证：`visible=58.4px` / 仅 `max-height:0` → `21.0px` / 补 padding+border 归零 → `0.0px`。

修复：`AdminTabLayout.vue` 的 `.is-hidden` 补 `padding-top:0;padding-bottom:0;border-bottom-width:0`，并把这三项与 `max-height` 一起加入 transition（显示态沿用 0.08s 延迟，隐藏态 0s）。

叠加第 3 项的修复后，5 个二级页面在侧栏展开时顶部统一为 20px（此前是 20+21=41px，数据字典配置 51px）。

## 5. tab 与内容的间距定为 6px

tab 可见时与下方内容原本是 **0px**（tab 条自身 8px padding-bottom 在边框之上，属内部间距）。

取值 **6px**，理由：项目既有紧邻节奏（工具栏→表格、表格→分页）均为 6px；tab 与其控制的内容属强关联，应比区块间距（14–16px）紧，又不能像 4px 那样紧贴 1px 边框读成一体。

实现必须规避的坑：**不能用父容器的 flex `gap`**（子项折叠到 0 高度后 gap 仍生效，会残留 6px），改用 tab 元素自身 `margin-bottom:6px` 并在 `.is-hidden` 归零、纳入 transition。

Chrome headless 实测：可见态 tab 高 58.4 / 到内容 **6.0px**；隐藏态 tab 高 0 / 内容距容器顶 **0.0px**（无残留）。

## 10. 维表/字典页行内编辑校验（修静默数据丢失 bug）

用户反馈：sort_order 输入字母/中文也保存。探查发现是**静默数据丢失**：
`save()` 第 418 行 `Number(row.sort_order) || 0` —— `"abc"` → `NaN` → `|| 0` → **存成 0**，不报错不提示，原排序值被毁、行跳到最前。后端 `sort_order: int` 本该对 "abc" 报 422，但前端已抹成 0，永远收不到脏值。

用户决策：保留行内编辑 + 补校验 / 两页一起改 / 后端补兜底。

改动：
- **新增** `src/composables/useRowValidation.ts` —— 按行 id 记录字段级错误；`fieldError(id,field)` 驱动 AppInput `:error` 红框、`check(row)` 返回首条错误（失焦/保存时调用）、`clearRow(id)` 保存成功后清理。两页共用，各自传 `validate` 函数。
- **AdminSettingsDict.vue**：4 个行内插槽加 `:error`/`:title`/`@blur="check(row)"`；`save()` 先 `check(row)`，有错 toast + **不发请求**；`parseSort`（`/^\d{1,6}$/`，0-999999）替代 `|| 0`；`submitValue()` 弹窗补 code 格式/长度 + sort 校验。CSS：`--num` 居中落到 `:deep(input)`。
- **AdminSettingsBase.vue**：value(≤2000)/remark(≤255) 同机制接入。
- **adminService.ts parseError**：422 的 `detail` 是数组，原 `return body?.detail` 会变 `[object Object]` → 数组时返回 `api.validationFailed` 文案。
- **后端 schemas.py**：`DimValueCreate/Update` 的 code 加 `pattern=^[A-Za-z0-9][A-Za-z0-9_.-]*$`、sort_order 加 `ge=0,le=999999`、remark 加 `max_length=255`；`SettingsPayload` value `max_length=2000`。

关键结论：
- **sort_order 保持 `type="text"` 而非 `type="number"`**：number 的 keydown 白名单让非法输入"完全无反应"比红框更不可发现，且 `onInput` 非法时 DOM 变而 model 不变，状态更隐蔽；90px 列也放不下 24px 步进器。
- **前端永不向 PUT 传 `sort_order:null`**：后端 `if body.sort_order is not None` 视 null 为"不更新"，会造成"用户以为改了却没变"。
- 实测数据库 20 行**零违反**新约束（code 最长 11/64、value 208/2000、sort 0-19/999999），加约束安全。
- 后端 PUT `sort_order:null` 返回 200（=不更新），是设计行为非 bug。
- `Object.values()` 对泛型映射类型推断出 `{}`，`check()` 返回值需 `as string | undefined` 断言。
